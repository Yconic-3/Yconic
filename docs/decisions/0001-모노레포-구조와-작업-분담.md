# 0001. 모노레포 구조와 작업 분담

- 날짜: 2026-11-06
- 상태: 채택
- 결정자: Yconic

## 배경

관리자 영역과 나머지 영역을 여러 사람이 동시에 개발하고 나중에 합친다.
각자 루트 설정이나 데이터 모양을 따로 만들면 합칠 때 충돌이 크게 난다.

## 결정

1. **루트 구조를 먼저 main에 넣는다.** pnpm workspace + Turborepo, 공통 TypeScript 설정(`packages/config`).
2. **데이터 모양은 `packages/shared-types` 하나로 약속한다.**
   - 운동 콘텐츠, 운동 단계, 제작 작업, 감사 로그, 관리자 역할, 운동 세션 상태
   - 역할별 권한표(`ROLE_PERMISSIONS`)와 콘텐츠 상태 전이 규칙(`CONTENT_TRANSITIONS`)
   - 콘텐츠 검사 규칙(`validateExerciseContent`): 필수 항목, 시각 의존 표현 경고 등
   - 프론트엔드는 화면 표시에, 백엔드는 실제 검증에 같은 규칙을 쓴다.
3. **shared-types를 바꿀 때는 PR에 `[공통 타입]`을 제목에 붙이고 모든 담당자에게 리뷰를 요청한다.**
4. **작업 분담** (각자 자기 폴더만 고친다)

| 영역 | 폴더 | 담당 |
| --- | --- | --- |
| 관리자 웹 | `apps/admin-web` | Yconic |
| 관리자 AI 에이전트 | `apps/admin-agent` | Yconic (다음 단계) |
| 사용자 앱 | `apps/user-app` | 미정 |
| 사용자 AI 에이전트 | `apps/user-agent` | 미정 |
| 백엔드 API | `apps/api` | 미정 |
| 백엔드 MCP | `apps/backend-mcp` | 미정 |
| 콘텐츠 제작 워커 | `apps/content-worker` | 미정 |

5. **백엔드가 준비되기 전에는 각 앱이 모의(mock) 데이터로 개발한다.**
   관리자 웹은 `AdminApi` 인터페이스 뒤에 모의 구현을 두고, 백엔드가 준비되면 HTTP 구현으로 바꾼다.

## 결과

- 장점: 각자 독립적으로 개발해도 데이터 모양과 권한 규칙이 같아서 합치기 쉽다.
- 단점: shared-types 변경은 여러 사람에게 영향을 주므로 신중하게 리뷰해야 한다.
