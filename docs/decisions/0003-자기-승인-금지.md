# 0003. 자기 승인 금지

- 날짜: 2026-11-06
- 상태: 채택
- 결정자: Yconic

## 배경

승인권자(APPROVER)와 최고 관리자(SUPER_ADMIN)는 편집 권한도 가지고 있다.
그래서 한 사람이 콘텐츠를 만들고, 고치고, 검수를 요청하고, 승인하고, 공개까지 혼자 할 수 있었다.
설계 문서는 "최종 승인은 별도 승인 권한을 가진 관리자가 수행한다"고 하므로, 만든 사람과 승인하는 사람을 나눠야 한다.

## 결정

1. **콘텐츠를 처음 만든 사람(`createdBy`)은 그 콘텐츠를 승인할 수 없다.**
   AI 초안은 영상을 올려 제작을 요청한 사람이 만든 사람이다.
2. **검수를 요청한 사람(`submittedBy`)도 승인할 수 없다.**
   남이 만든 초안을 직접 고쳐 검수 요청한 뒤 스스로 승인하는 우회를 막기 위해서다.
3. **역할과 상관없이 적용한다.** 최고 관리자도 예외가 아니다.
4. **막는 것은 승인(APPROVE)뿐이다.** 수정 요청, 공개, 공개 중단, 보관은 막지 않는다.
   다른 사람이 승인한 콘텐츠를 만든 사람이 공개하는 것은 허용한다.
5. 규칙은 `packages/shared-types`의 `selfApprovalBlockedReason`에 있다. 화면은 승인 버튼을 잠그고 이유를 보여 주며, 백엔드는 같은 함수로 403을 돌려준다.

## 결과

- 콘텐츠 하나를 공개하려면 승인 권한이 있는 사람이 최소 한 명 더 필요하다.
- 팀에 승인 권한자가 한 명뿐이면 그 사람이 만든 콘텐츠는 승인할 수 없다. 이 경우 승인권자를 한 명 더 두거나, 편집자가 초안을 만들고 검수를 요청해야 한다.
- `ExerciseContent`에 `submittedBy` 필드가 생겼다. 검수 요청 때 기록한다.
