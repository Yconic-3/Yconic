# user-app — 사용자 앱

시각장애인 사용자가 **말로 운동을 찾고, 구간별 음성 안내를 들으며 운동하는** 모바일 웹 화면이다.
화면은 디자인 시안 B(말벗핏)의 "세로 한 줄 구조"를 따른다.

콘텐츠는 관리자 웹에서 공개한 영상과 구간별 음성 안내다 (`docs/decisions/0002-영상-중심-콘텐츠-모델.md`).
앱은 영상(또는 시간)을 재생하다가 구간이 시작될 때 그 구간의 `voiceGuide`를 읽어 준다.

## 실행

```bash
pnpm install
```

```bash
pnpm dev:user
```

http://localhost:3000 에서 열린다. 백엔드 없이 **모의 데이터 모드**로 동작한다.

- 예시 콘텐츠 4건이 앱에 들어 있다 (`src/lib/api/mock/seed.ts`). 관리자 웹과 실행 주소가 달라 관리자 웹에서 만든 모의 데이터는 보이지 않는다.
- 예시 콘텐츠에는 영상 파일이 없다. 이때는 영상 없이 시간만 흘려 구간 안내를 들려준다.
- 음성 인식은 Chrome 계열 브라우저에서 마이크를 허용해야 동작한다. 안 되는 환경에서는 화면의 "말 대신 글로 입력"으로 같은 기능을 쓴다.

## 화면 구조

한 페이지 안에서 화면이 바뀐다. 구역 순서는 항상 같다.

| 구역 | 내용 |
| --- | --- |
| 화면 이동 | 이전 화면으로(돌아갈 곳 이름 표시), 홈으로 가기. 홈에서는 나오지 않는다 |
| 방금 안내 | 앱이 마지막으로 한 말과 내가 한 말, 다시 듣기 |
| 재생 조작 | 시작/멈춤, 다음 단계, 지금 단계 다시 듣기, 이전 단계, 주의사항 (운동 화면) |
| 전체 단계 | 구간 목록. 누르면 그 구간으로 간다 (운동 화면) |
| 운동 고르기 | 공개 중인 운동 목록 (홈·목록 화면) |
| 말하기 속도 | 느리게, 빠르게 |
| 이렇게 말해 보세요 | 지금 화면에서 쓸 수 있는 말. 누르면 그 말을 한 것처럼 동작한다 |
| 말 대신 글로 입력 | 음성 인식이 안 될 때 쓰는 입력칸 |
| 마이크 | 화면 맨 아래 고정. 누르면 계속 듣는다 |

### 접근성 원칙 (바꿀 때 지킬 것)

- **한 줄에 하나.** 버튼은 화면 폭 전체를 차지하고 위에서 아래로만 쌓는다. 가로로 나란히 놓거나 가로로 넘기는 목록을 만들지 않는다. 스크린리더로 넘기는 순서와 화면 위치가 같아야 한다.
- **상태는 글로.** 색이나 아이콘만으로 상태를 알리지 않는다. 현재 단계에는 "(지금)", 목록에는 "스트레칭, 초급, 1분 15초"처럼 문장을 붙인다.
- **말이 먼저.** 앱의 모든 응답은 소리로 먼저 나가고, 화면의 "방금 안내"는 그 기록이다. 음성이 안 되는 환경에서도 화면 글과 버튼만으로 모든 기능을 쓸 수 있어야 한다.
- 화면이 바뀌면 맨 위로 올리고 제목으로 초점을 옮긴다.
- 색은 `src/app/globals.css`의 토큰만 쓴다. 글자는 바탕과 4.5:1 이상, 누를 수 있는 요소의 테두리는 3:1 이상이다. 장식용 선(`line`)을 버튼 테두리로 쓰지 않는다.
- 터치 영역은 높이 60px 이상.

## 쓸 수 있는 말

| 말 | 동작 |
| --- | --- |
| "스트레칭 찾아줘", "하체 운동 추천해줘" | 분류(스트레칭·근력·유산소·균형·재활)나 태그로 목록 열기 |
| "스쿼트", "스쿼트 시작" | 운동 열기 / 열고 바로 시작 |
| "시작", "계속" | 시작 또는 이어서 재생 |
| "멈춰", "잠깐" | 멈춤 |
| "다음", "이전", "다시" | 단계 이동, 지금 단계 다시 듣기 |
| "느리게", "빠르게" | 말하기 속도 |
| "이전 화면", "뒤로 가기", "홈" | 화면 이동 ("이전"만 말하면 이전 단계) |
| "도움말" | 쓸 수 있는 말 안내 |
| "아파요", "어지러워요", "숨이 차요" | **운동을 바로 멈추고** 쉬도록 안내 (다른 말보다 먼저 처리) |

말을 해석하는 규칙은 `src/lib/intent.ts`에 있다. 사용자 AI 에이전트(`apps/user-agent`)가 준비되면 이 자리를 에이전트 호출로 바꾼다.
앱은 가진 콘텐츠 안에서만 답하고, 없는 운동 정보를 지어내지 않는다. 의료적 판단도 하지 않는다 (설계 문서 10장).

## 구조

```
src/
├── app/                        # Next.js 페이지, 색 토큰(globals.css)
├── components/
│   ├── assistant-app.tsx       # 화면 전체 (구역 배치, 말·버튼 처리)
│   └── ui.tsx                  # 한 줄 버튼, 구역 제목, 아이콘
└── lib/
    ├── api/
    │   ├── user-api.ts         # UserApi 인터페이스 (화면은 이것만 사용)
    │   ├── http-user-api.ts    # 백엔드 HTTP 구현 (경로는 임시)
    │   └── mock/               # 모의 구현과 예시 콘텐츠
    ├── intent.ts               # 말 → 할 일 (테스트 있음)
    ├── player.ts               # 시각 ↔ 구간 계산, 세션 상태 (테스트 있음)
    ├── navigation.ts           # 화면 이동과 이전 화면 기록 (테스트 있음)
    ├── use-exercise-session.ts # 재생 진행: 주의사항 → 구간별 안내 → 완료
    ├── speech.ts               # 음성 출력 (음성 파일 또는 브라우저 음성)
    └── recognition.ts          # 음성 인식
```

데이터 모양은 `@yconic/shared-types`에서 가져온다. 사용자에게 넘어오는 콘텐츠는 `ExerciseContent`에서
필요한 칸만 고른 것이며(`PublishedExercise`), 관리자 내부 메모·검수 의견은 포함하지 않는다.

## 다른 영역과의 접점

| 담당 | 필요한 것 | 지금 상태 |
| --- | --- | --- |
| 백엔드 `apps/api` | 공개 콘텐츠 목록·상세, 영상 재생 주소 | 엔드포인트가 공통 타입에 아직 없다. `http-user-api.ts`의 경로는 임시 |
| 백엔드 `apps/api` | 운동 세션 상태 관리 (시작·멈춤·단계 이동) | 설계상 백엔드 담당. 지금은 앱 안에서 계산 (`player.ts`의 `sessionStateFor`) |
| 워커 `apps/content-worker` | 구간별 음성 파일 | `tts.audioUrl`이 재생 가능한 주소면 그 파일을, 아니면 브라우저 음성으로 읽는다 |
| 사용자 AI `apps/user-agent` | 자연어 이해, 대화 | 지금은 `intent.ts`의 낱말 규칙 |

### 백엔드 연결

`.env.example`을 `.env.local`로 복사하고 모드를 바꾼다.

```
NEXT_PUBLIC_USER_API_MODE=http
NEXT_PUBLIC_API_BASE_URL=http://localhost:4000
```

## 테스트

```bash
pnpm --filter @yconic/user-app test
```

말 해석(위험 신호 우선, 화면 이동과 단계 이동 구분, 분류·태그·이름 찾기), 구간 계산과 세션 상태,
화면 이동 기록, 모의 API(공개 콘텐츠만 노출, 내부 정보 제외), 예시 콘텐츠의 공통 검사 규칙 통과를 검증한다.

## 아직 없는 것

- **수강 경험에 따른 맞춤 안내** (배운 동작은 간결하게, 처음 하는 동작은 상세하게). 간결/상세 두 벌의 안내문과 수강 강의 정보가 공통 타입에 없다. `[공통 타입]` 논의가 먼저 필요하다.
- 로그인, 운동 이력, 사용자 설정 저장 (말하기 속도는 새로 고치면 처음 값으로 돌아간다)
- 사용자 AI 에이전트 연결, 말 끼어들기(barge-in): 안내가 나오는 중에 마이크가 안내 소리를 명령으로 들을 수 있다
- PWA 설치(매니페스트·오프라인)
- VoiceOver·TalkBack 실제 기기 검증
- 영상 자막
