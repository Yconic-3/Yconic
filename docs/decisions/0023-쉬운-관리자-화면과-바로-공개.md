# 0023. 쉬운 관리자 화면과 바로 공개

- 날짜: 2026-11-28
- 상태: 채택
- 결정자: Yconic

## 배경

관리자 화면이 너무 복잡했다.

- 메뉴가 넷(대시보드, 운동 영상, AI 제작 작업, 감사 로그)이고, 상태가 여섯 가지(초안, 검수 중, 수정 요청, 승인됨, 공개 중, 보관됨), 상태를 바꾸는 단추가 일곱 가지였다.
- 편집 화면이 아주 길었다. 구간마다 일곱 칸이 모두 펼쳐져 있어서, 구간이 12개인 영상은 화면을 한참 내려야 했다.
- 영상 하나를 공개하려면 검수 요청 → 승인 → 공개를 차례로 눌러야 했고, 자기 승인 금지(결정 0003) 때문에 혼자 운영하면 자기가 올린 영상은 끝내 공개할 수 없었다.
- 회원이 올린 초안(예: 스쿼트 영상)을 관리자가 화면에서 바로 공개할 방법도 없었다. 올린 회원이 먼저 검수를 요청해야 했다.

유튜브 관리 화면처럼 쉽게, 한눈에 알 수 있게 바꾼다.

## 결정

### 1. 공개 상태는 넷으로 보여 준다

여섯 가지 상태는 그대로 두되(데이터와 API는 바뀌지 않는다), 화면에는 묶어서 보여 준다 (`visibilityOf`).

| 화면에 보이는 말 | 실제 상태 |
|---|---|
| 공개 | 공개 중 |
| 비공개 | 초안, 수정 요청(돌려보냄), 승인됨 |
| 공개 요청 | 검수 중 |
| 보관 | 보관됨 |

### 2. "공개하기" 한 번으로 공개한다 (`PUBLISH_NOW`)

- 승인 권한과 공개 권한이 있는 사람(승인권자, 최고 관리자)은 초안·돌려보낸 것·공개 요청 들어온 것을 한 번에 공개할 수 있다. 승인과 공개를 한 번에 하는 것이다.
- 승인을 포함하므로 **자기 승인 금지가 그대로 적용된다.** 만든 사람과 공개를 요청한 사람은 바로 공개할 수 없다.
- 검수 요청을 건너뛰므로, 서버가 검사 규칙(오류 없음)을 확인한다. 오류가 있으면 공개하지 않는다.
- 기록에는 "승인과 공개를 한 번에"라고 남는다.
- 검수 요청 → 승인 → 공개를 차례로 하는 예전 길도 그대로 된다. 회원과 편집자는 지금처럼 공개를 요청한다.

### 3. 자기 승인 금지에서 최고 관리자만 예외로 한다 (결정 0003을 바꾼다)

- **최고 관리자는 자기가 올렸거나 공개를 요청한 것도 승인하고 바로 공개할 수 있다.**
- 승인권자는 예전과 같다. 남이 올린 것만 공개할 수 있고, 자기가 올린 것은 화면에 "공개하기" 대신 "공개 요청"이 나온다.
- 까닭: 지금은 운영하는 사람이 한 명이다. 규칙을 그대로 두면 관리자 계정을 두 개 만들어 번갈아 써야 하는데, 그러면 규칙이 지키려던 것(두 사람이 확인)은 지켜지지 않고 번거롭기만 하다. 팀이 커지면 최고 관리자가 아닌 사람들에게는 두 사람 확인이 그대로 남는다.
- 설계 문서의 "최종 승인과 사용자 공개는 별도 승인 권한을 가진 관리자가 수행한다"는 지켜진다. 편집자·회원·AI는 여전히 공개할 수 없다.
- 승인권자가 남이 올린 초안을 고친 뒤 바로 공개하는 것은 막지 않는다. 올린 사람과 공개하는 사람이 다르기 때문이다.

### 4. 공개 중인 것을 고치려면 "비공개로 돌려 고치기" (`REVISE`)

- 승인됐거나 공개 중인 콘텐츠를 초안으로 돌린다. 공개 중이었으면 사용자 화면에서 사라진다.
- 다 고친 뒤 다시 공개한다. 공개 중인 내용이 도중에 바뀌지 않게 잠그는 것은 예전과 같다.
- "비공개로"(`UNPUBLISH`)는 예전처럼 내용을 그대로 둔 채 숨기기만 한다. 다시 공개할 때 승인이 필요 없다.

### 5. 화면 구성

- **메뉴는 둘**: 콘텐츠, 기록(최고 관리자만). 위쪽 머리말에 있고, 그 옆에 "영상 올리기" 단추가 있다.
  - 대시보드는 없앴다. `/admin`은 콘텐츠 목록으로 간다.
  - AI 제작 작업 목록은 메뉴에서 뺐다. 분석 중이거나 실패한 영상은 콘텐츠 목록 맨 위에 나오고, 내역 전체는 그 옆의 "분석 내역"으로 연다.
- **콘텐츠 목록**: 영상 한 장면, 제목, 요약, 공개 상태, 그리고 그 줄에서 바로 누르는 "공개하기 / 비공개로". 위에는 전체·공개·비공개·공개 요청 탭.
- **편집 화면**
  - 왼쪽은 탭 셋: 구간 안내, 기본 정보, 더보기(영상 파일·날짜·기록·단축키·보관).
  - 오른쪽은 영상과 "고칠 것"이 화면을 내려도 따라온다. 좁은 화면에서는 영상이 위에 온다.
  - 구간은 한 줄씩 보이고, 누른 구간 하나만 펼쳐진다. 펼치면 제목과 음성 안내문이 먼저 나오고, 시각·종류·반복 횟수·짧은 안내는 "시간과 자세한 설정" 안에 있다.
  - 저장 단추는 고친 것이 있을 때만 화면 아래에 나타난다.
  - 맨 위 오른쪽의 큰 단추 하나가 그 사람이 지금 할 수 있는 일이다: 공개하기, 비공개로, 공개 요청. 어떤 단추를 보여 줄지는 `apps/web/src/admin/lib/content-plan.ts`가 정한다.
- **구간별 "음성 생성" 단추와 "음성 파일이 준비되지 않았습니다" 경고는 화면에서 뺐다.** 음성은 서버 목소리(결정 0021)가 그때그때 만들기 때문에, 구간마다 미리 만드는 예전 기능은 쓰이지 않는다. API와 검사 규칙은 그대로 두었다.

## 결과

- 회원이 올린 초안을 관리자가 목록에서 바로 공개할 수 있다.
- 최고 관리자 혼자서 영상을 올리고, 고치고, 공개할 수 있다.
- 공통 타입에 행동 둘(`PUBLISH_NOW`, `REVISE`)과 `visibilityOf`, `publishActionFor`가 생겼다. `selfApprovalBlockedReason`에 역할을 넘기는 넷째 값이 생겼다 (넘기지 않으면 예외 없이 막는다).
- 화면에서 "승인"만 따로 하는 단추와 승인된 것을 돌려보내는 단추는 없어졌다 (API로는 된다). 공개 요청이 들어온 것은 "공개하기"와 "돌려보내기"로 처리한다.
- 남의 영상을 공개해도 되는지(저작권)는 화면이 막아 주지 않는다. 공개하는 사람이 확인해야 한다.

## 확인하지 못한 것

- 실제 서버 데이터로 관리자 화면을 써 보는 것 (예시 데이터 모드의 브라우저와 API 테스트로 확인했다).
- 화면 읽기 프로그램(스크린 리더)으로 새 화면을 써 보는 것.
