  - 결정 기록: `docs/decisions/0007-시안-D-소리벗과-회원-콘텐츠-올리기.md`

  - 로그인한 회원이면 누구나 영상을 올리고, AI가 찾은 '화면에서만 전달되던 정보'와 안내 초안을 확인해 검수를 요청한다.
  - 공개는 지금처럼 승인권자만 한다.
- **내 강의** (`/courses`): 배운 강의의 동작은 짧은 안내로 읽는다. 관리자 구간 편집기에 "배운 사람용 짧은 안내" 칸이 생겼다.
- **DB가 바뀌었다**: `git pull` 뒤 `pnpm db:migrate`를 한 번 돌린다. 예시 데이터의 짧은 안내까지 받으려면 `pnpm db:seed`를 돌린다.

## 2026-11-11 · Yconic (사용자 AI 에이전트 — 말로 운동 찾기·조작)

- **사용자 AI 에이전트 `apps/user-agent`(포트 4100)를 붙였다.** "무릎에 무리 없는 하체 운동 있어?", "그거 할래"처럼 자연스러운 말을 Claude로 알아듣는다. 결정 기록: `docs/decisions/0006-사용자-AI-에이전트.md`
- 실행: `pnpm dev:agent`. AI를 켜려면 `apps/user-agent/.env`에 `ANTHROPIC_API_KEY`를 넣는다 (커밋 금지). 키가 없거나 에이전트를 안 켜도 웹앱은 예전 규칙 기반으로 그대로 동작한다.
- Claude 연결은 공통 패키지 `packages/ai-common`에 있다. 관리자 에이전트도 이것을 쓴다.
- **임시인 것**: 설계 문서의 backend-mcp 없이 에이전트가 API를 HTTP로 바로 부른다. 관리자 에이전트 때 MCP로 바꾼다.

## 2026-11-11 · Yconic (데이터베이스와 API — 이제 웹앱이 서버 데이터를 쓴다)

- **PostgreSQL 18 + NestJS API를 붙였다.** 사용자 화면·관리자 화면·로그인이 모두 API를 쓴다. 결정 기록: `docs/decisions/0005-데이터베이스와-API-구성.md`
- **실행 순서가 바뀌었다**: `pnpm install` → `pnpm db:start`(창 열어 두기) → 처음 한 번 `pnpm db:setup` → `pnpm dev:api` → `pnpm dev:web`. Docker는 필요 없다.
- 서버 없이 화면만 보려면 `apps/web/.env.local`에 `NEXT_PUBLIC_API_MODE=mock`.
- 테이블 설명은 `docs/database.md`, API 주소는 `apps/api/README.md`와 `packages/shared-types`의 `admin-api.ts`, `user-api.ts`, `auth.ts`.
- **임시인 것**: 제작 작업기는 API 서버 안에서 모의 분석기로 돈다. 올린 영상은 `apps/api/storage`에 저장된다 (S3로 옮길 예정).
- **CI**: PR 검사에 API 테스트가 추가됐다 (PostgreSQL 서비스 컨테이너 사용).

- **백엔드 담당자**: 인증 방식이 정해지면 `apps/web/src/mock/auth.ts` 자리를 실제 인증으로 바꾸고, `/admin` 아래는 서버에서 막아야 한다.

## 2026-11-11 · Yconic (사용자 앱 + 관리자 웹 → 한 웹앱)

- **사용자 앱과 관리자 웹을 한 웹앱 `apps/web`으로 합쳤다.** `pnpm dev:web` 하나로 실행한다. 사용자 화면은 http://localhost:3000 , 관리자 화면은 http://localhost:3000/admin .
- 이제 두 화면이 같은 모의 저장소를 쓴다. 관리자가 영상을 올려 공개하면 사용자 화면 목록에 바로 나온다.
- 예시 데이터를 하나로 합쳤다: 공개 운동 4개 + 관리자 흐름 시연용 3개(검수 중·초안·수정 요청, 다른 운동으로 바꿈).
- 코드 위치: 사용자 화면 `apps/web/src/user`, 관리자 화면 `apps/web/src/admin`, 함께 쓰는 모의 백엔드 `apps/web/src/mock`. 서로의 화면 코드는 가져다 쓰지 않는다.
- `pnpm dev:admin`, `pnpm dev:user`는 없어졌다. 예전 브랜치에서 작업 중이면 main을 받은 뒤 위 경로로 옮겨 주세요.
- 결정 기록: `docs/decisions/0004-한-웹앱으로-합치기.md`

- 공통 타입은 바꾸지 않았다. 작업 분담표에서 사용자 앱 담당을 Yconic으로 적었다.
- **백엔드 담당자**: 사용자용 엔드포인트가 아직 공통 타입에 없다. `apps/user-app/src/lib/api/http-user-api.ts`의 경로(`/exercises`, `/exercises/:id`, `/videos/:id/playback-url`)는 임시다. 정해지면 `[공통 타입]` PR로 기록해 주세요.
- **논의 필요**: 기획안의 "수강 경험에 따라 배운 동작은 간결하게, 처음 하는 동작은 상세하게" 기능은 넣지 않았다. 간결/상세 두 벌의 안내문과 수강 강의 정보가 공통 타입에 없기 때문이다. 넣으려면 `[공통 타입]` 논의가 먼저 필요하다.
- 운동 세션 상태는 설계상 백엔드가 관리한다. 지금은 앱 안에서 계산하고 있으니 `apps/api`가 준비되면 옮긴다.
