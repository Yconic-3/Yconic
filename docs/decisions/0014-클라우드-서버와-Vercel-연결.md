# 0014. 클라우드 서버에 올리고 Vercel 주소로 연결

- 날짜: 2026-11-28
- 상태: 채택
- 결정자: Yconic

## 배경

뮤즈 클라우드 서버(이모션웨이브) 한 대를 받았다. 그동안 Vercel 주소는 예시 데이터로만 돌았고, 데이터는 보는 사람의 브라우저에만 남았다.
서버에는 조건이 있다.

- 바깥에 열리는 포트는 하나뿐이고, 주소(`https://k7m4q9vz.cloud.aimple.io`)는 업체가 정해 준 것이다.
- 서버에서 밖으로는 HTTP/HTTPS만 나간다.
- CPU 2개, 메모리 3.3GB, 그래픽카드 없음.

## 결정

1. **DB·API·AI 에이전트·웹앱을 모두 이 서버에서 켠다.**
   - 포트가 하나라서 서버에서도 웹앱을 8080번에 켜고, 웹앱이 `/api`, `/agent`를 대신 연결한다 (결정 0010과 같은 방식).
   - 네 개 모두 systemd 서비스로 등록해 죽거나 재부팅되어도 다시 켜지게 한다.
2. **사용자가 쓰는 주소는 Vercel 주소 그대로 둔다.**
   - Vercel의 웹앱이 `/api`, `/agent`를 서버 주소로 대신 연결한다 (`API_INTERNAL_URL`, `AGENT_INTERNAL_URL`).
   - 이미 알려진 주소를 바꾸지 않아도 되고, 서버를 옮겨도 Vercel 환경 변수만 바꾸면 된다.
   - Vercel 안에서 돌던 AI 대화(`AGENT_IN_WEB`)는 끄고 서버의 에이전트를 쓴다.
3. **서버 DB의 관리자 비밀번호는 무작위 값으로 바꾼다.**
   - 저장소가 공개라 예시 관리자 비밀번호도 공개되어 있다. 결정 0010의 관리자 로그인 막기는 Cloudflare 임시 링크에만 적용된다.
   - 새 비밀번호는 서버에만 둔다. 화면의 체험 계정에는 일반 회원만 보인다.
4. **AI는 하루 한도 안에서만 쓴다.** 대화 300번, 영상 분석 5번, 맞춤 안내 100번.

설치·업데이트 방법은 `docs/deploy-cloud.md`에 있다.

## 결과

- 좋은 점: 데이터가 서버 DB에 남는다. 영상을 올리면 실제 분석기가 돈다. 주소는 그대로다.
- 한계
  - 업체 프록시가 약 1MB보다 큰 올리기를 막는다. 영상을 나눠 올려서 해결했다 (결정 0015).
  - 코드를 병합해도 서버는 자동으로 업데이트되지 않는다. 사람이 접속해서 받아야 한다.
  - 서버가 꺼지면 Vercel 주소도 데이터를 불러오지 못한다. 백업이 없다.
  - 받아쓰기가 CPU로 돌아 느리다.
  - 누구나 가입해 영상을 올릴 수 있다 (공개는 승인권자만). 가입과 구글 로그인은 결정 0016.
- 나중에: 자동 배포, 백업, 설계 문서의 S3·BullMQ·TTS.
