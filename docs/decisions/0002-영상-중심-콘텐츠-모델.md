# 0002. 영상 중심 콘텐츠 모델

- 날짜: 2026-11-06
- 상태: 채택
- 결정자: Yconic

## 배경

처음 만든 관리자 웹은 콘텐츠를 제목·단계·안내문 같은 글 묶음으로 다루고 영상은 파일 이름만 적어 두는 부속 정보였다.
그러나 이 플랫폼에서 운동 콘텐츠의 본체는 **영상**이다. 누군가 영상을 올리면 그 영상을 처리하는 것이 핵심이다.

## 결정

1. **영상을 올리는 사람은 관리자·트레이너뿐이다.** 시각장애인 사용자는 결과만 이용한다.
2. **콘텐츠 = 영상(`VideoAsset`) + 영상 타임라인 위의 구간(`ExerciseSegment[]`)**
   - 구간마다 시작·끝 시각, 종류(준비·운동·휴식·마무리), 음성 안내문, 음성 파일 상태를 가진다.
   - 사용자 앱은 영상을 재생하다가 구간 시작 시각에 음성 안내를 들려준다. 영상에 음성을 합성한 새 파일은 만들지 않는다.
3. **처리 흐름**: 영상 업로드 → 저장소 보관 → 제작 작업 큐 → 영상 분석(동작 구간 찾기) → 구간별 안내문 생성 → 구간별 음성 생성 → 초안 → 관리자가 영상을 보며 구간·안내문 검수 → 승인 → 공개
4. **분석기는 교체 가능한 자리로 둔다.** `VideoAnalysisResult`(shared-types)가 분석기와 나머지 시스템 사이의 약속이다.
   - 지금은 영상 길이만으로 구간을 나누는 모의 분석기를 쓴다.
   - content-worker 담당자가 실제 분석(프레임 추출 + 비전 모델)을 이 형식으로 구현한다.
5. **검사 규칙에 영상 특성을 반영한다.** 구간이 영상 길이를 넘거나 겹치면 오류, 안내문을 읽는 시간이 구간 길이보다 길면 경고.

6. **음성 안내가 없는 구간이 있어도 공개할 수 있다.** (2026-11-06 추가)
   이 플랫폼은 일반 사용자와 시각장애인 사용자가 함께 이용한다. 음성 미생성·재생성 필요는 경고로만 알리고 공개를 막지 않는다.
   음성이 없는 구간은 안내 없이 영상만 재생된다.
7. **영상 교체와 다시 분석** (2026-11-06 추가)
   - 영상 교체: 초안·수정 요청 상태에서 영상만 바꾼다. 구간은 그대로 두고, 길이가 맞지 않으면 검사 규칙이 알려 준다.
   - 다시 분석: 현재 영상을 다시 분석해 구간과 안내문을 통째로 새 결과로 바꾼다. 제목·요약·주의사항은 유지한다.
     분석 중에는 수정·검수 요청을 막고, 그 사이 콘텐츠가 수정할 수 없는 상태가 되면 결과를 반영하지 않고 작업을 실패로 끝낸다.
   - 제작 작업에 `kind`(CREATE / REANALYZE)를 두어 두 경우를 같은 큐에서 처리한다.

## 결과

- 관리자 웹은 영상 플레이어와 타임라인을 중심으로 재작성했다. 영상을 보면서 "현재" 시각으로 구간을 잡고, 브라우저 음성으로 사용자가 들을 안내를 미리 들을 수 있다.
- 모의 모드에서 영상은 브라우저 IndexedDB에 보관된다. 백엔드가 준비되면 S3 호환 스토리지로 올리고 재생 주소를 받는다.
- 백엔드에 필요한 엔드포인트 두 개가 늘었다: 영상 업로드, 재생 주소 조회 (`packages/shared-types/src/admin-api.ts`).
