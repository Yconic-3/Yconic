# 0008. 실제 영상 분석과 동작 단위 맞춤 안내

- 날짜: 2026-11-12
- 상태: 채택
- 결정자: Yconic

## 배경

지금까지 영상 분석기는 모의 분석기였다. 영상을 실제로 보지 않고 길이에 맞춰 정해 둔 단계를 돌려줬다.
맞춤 안내도 강의 단위였다. '하체 강의'를 들었으면 하체 꼬리표가 붙은 영상 전체를 짧게 안내했다.

확인하고 싶은 것은 두 가지였다.

1. 실제 운동 영상(예: 5분 스쿼트 루틴)을 올리면 그 영상에 맞는 단계별 음성 안내를 만들 수 있는가.
2. 사용자가 배운 것에 따라 안내가 달라지는가.
   스쿼트 기초를 배운 사람에게는 스쿼트 자세를 짧게 안내하고, 팔굽혀펴기를 배운 사람에게는 팔굽혀펴기를 짧게 안내해야 한다.
   한 영상이 아니라 그 동작이 나오는 **다른 영상에서도** 똑같이 적용돼야 한다.

## 결정

1. **실제 분석기를 쓴다** (`packages/content-analysis/src/claude`).
   - ffmpeg로 장면을 뽑는다. 최대 90장, 폭 512px.
   - faster-whisper(`scripts/transcribe.py`, 이 컴퓨터에서 무료로 돈다)로 강사의 말을 받아 적는다.
   - Claude(`claude-opus-5-5`)에게 장면 사진과 받아 적은 말을 함께 준다.
   - Claude는 단계(시각, 제목, 자세한 안내, 짧은 안내, 동작)와 '화면으로만 전달되던 정보'를 정해진 JSON 모양으로 돌려준다.
   - 받아쓰기가 실패해도 장면만으로 분석하고 경고를 남긴다.
   - API에 `ANTHROPIC_API_KEY`가 있으면 실제 분석기를 쓰고, 없거나 `VIDEO_ANALYZER=mock`이면 모의 분석기를 쓴다.
   - 실제 분석은 몇 분 걸린다. 그래서 작업기는 분석을 DB 트랜잭션 밖에서 돌리고, 진행 단계를 작업 상태에 남긴다.
2. **단계마다 동작(movement)을 붙인다** (`packages/shared-types/src/movements.ts`).
   - 정해진 동작 목록(`MOVEMENT_IDS`)에서 고른다: 스쿼트, 런지, 팔굽혀펴기, 벽 팔굽혀펴기, 힙 힌지 …
   - 분석기가 붙이고, 운영자가 고칠 수 있다.
   - 영상끼리 같은 동작을 알아보는 열쇠가 이 동작 목록이다.
3. **사용자마다 학습 프로필을 둔다** (`account_movements` 테이블, API `/me/learning`).
   - 동작을 아는 경로는 세 가지다.
     - 강의로 배움: 강의를 등록하면 그 강의의 동작들을 안다.
     - 직접 알림: "스쿼트 배웠어"라고 말하거나 '내 동작' 화면에서 켠다.
     - 연습: 그 동작이 나오는 영상을 끝까지 3번(`PRACTICE_THRESHOLD`) 따라 한다.
   - 강사에게 배운 용어도 적어 둘 수 있다. 예: "엉덩이 의자 = 엉덩이를 뒤로 빼며 앉기".
4. **안내 수준은 영상이 아니라 단계마다 정한다.**
   - 단계에 붙은 동작을 모두 알면 짧게, 하나라도 처음이면 자세하게 안내한다.
   - 그래서 스쿼트를 배운 사람이 5분 스쿼트 영상을 보면, 스쿼트 단계는 짧게, 처음 하는 힙 힌지 단계는 자세하게 듣는다.
5. **AI가 사용자별로 안내를 다시 쓴다** (`GET /me/guides/:exerciseId`).
   - 공개된 운동만 다시 쓴다.
   - 그 영상에 사용자가 아는 동작이 하나라도 있을 때만 Claude를 부른다.
   - Claude는 아는 동작은 배운 용어로 짧게 쓴다. 처음 하는 동작은 이미 아는 동작에 빗대어 자세하게 쓴다.
     예: "스쿼트에서 배운 엉덩이 의자처럼 엉덩이를 뒤로 빼는 동작인데 …"
   - 결과는 (사용자, 콘텐츠)마다 `personalized_guides`에 저장해 두고 다시 쓴다.
     학습 프로필이나 콘텐츠가 바뀌면 저장 열쇠(profileKey)가 달라져서 새로 만든다.
   - 다음 경우에는 그 단계만 규칙 안내로 둔다. 규칙 안내는 미리 만든 자세한 안내와 짧은 안내 중 하나를 고른 것이다.
     - AI 응답이 비었을 때
     - 400자를 넘을 때
     - "이렇게", "여기" 같은 화면 의존 표현이 있을 때
     - AI를 쓸 수 없을 때
6. **음성 파일은 아직 만들지 않는다.**
   - 맞춤 안내 글은 사용자의 기기 음성(브라우저 TTS)이 읽는다.
   - 실제 분석기가 만든 단계의 음성 상태는 `NONE`이다.

## 확인한 결과 (실제 영상 1편)

'하루 한 번! 기초체력 기르는 5분 스쿼트'(5분 37초)를 올려 확인했다.

- **분석**: 받아쓰기 35줄, 장면 84장이 나왔다. 분석에 94초 걸렸다.
  - 단계 11개가 나왔다: 소개, 힙 힌지, 베이직 스쿼트, 프론트 레이즈 스쿼트, 홀딩 스쿼트, 와이드 스쿼트와 그 사이 휴식.
  - 화면으로만 전달되던 정보 8개를 찾았다. 예: "45초 운동, 15초 휴식"이 자막으로만 나옴, 손 위치가 시범으로만 나옴.
- **스쿼트를 배운 사람**: 스쿼트 단계 3개는 짧게, 배운 용어로 안내했다. 힙 힌지와 프론트 레이즈 스쿼트는 자세하게 안내했다.
- **상체 강의를 들은 사람**: 스쿼트 단계는 모두 자세하게 안내했다. 힙 힌지는 "팔굽혀펴기에서 몸을 일자로 유지했던 것처럼"에 빗대어 설명했다.
- **다른 영상에도 적용**: 스쿼트를 배운 사람은 '의자 잡고 스쿼트'에서도 스쿼트 단계가 짧았다.
  상체 강의를 들은 사람은 '벽 밀기 상체 운동'이 짧았다.
  아는 동작이 없는 영상('목 스트레칭' 등)은 AI를 부르지 않았다.

## 결과

- 좋은 점
  - 운영자가 영상만 올리면 단계와 음성 안내 초안이 나온다. 화면으로만 전달되던 정보도 찾아 준다.
  - 사용자가 배운 것이 영상 경계를 넘어 쌓인다.
- 비용
  - 5분 영상 분석 한 번에 Claude 사용료가 대략 0.1~0.3달러 든다.
  - 맞춤 안내는 (사용자, 영상)마다 처음 한 번만 몇 센트가 들고, 그다음은 저장본을 쓴다.
- 서버 준비물
  - ffmpeg, Python과 faster-whisper가 필요하다. Whisper 모델은 처음 실행할 때 약 460MB를 내려받는다.
  - 없으면 `VIDEO_ANALYZER=mock`으로 끈다.
- 아직 임시인 것
  - 분석은 API 서버 안에서 돈다. 설계 문서의 BullMQ 작업기로 옮길 예정이다.
  - 영상은 서버 폴더에 저장된다. S3로 옮길 예정이다.
  - 음성 파일 생성(TTS 공급자)은 나중에 붙인다.
- 저작권
  - 남이 만든 영상(유튜브 등)은 개인 시험에만 쓴다.
  - 공개하려면 만든 사람의 허락이 필요하다.
