# 0022. 큰 영상 빠르게 올리기

- 날짜: 2026-11-28
- 상태: 채택
- 결정자: Yconic

## 배경

영상을 작은 조각으로 나눠 올리게 한 뒤(결정 0015) 남은 문제가 셋 있었다.

- 조각을 하나씩 차례로 보내서 느렸다. 1GB면 조각이 1,300개가 넘는다.
- 올리기와 재생이 모두 Vercel을 거쳤다. Vercel 무료 요금제는 서버로 넘기는 전송량이 한 달 10GB라서, 1GB 영상을 몇 번 올리고 재생하면 한도에 닿는다.
- 올리다 끊기면 처음부터 다시 올려야 했다.

업체 프록시(nginx)가 받는 요청 크기는 재 보니 정확히 1MiB(1,048,576바이트)였다. 이 한도는 우리가 바꿀 수 없다.

## 결정

1. **조각을 어떤 순서로 보내도 되게 하고, 화면은 4개씩 동시에 보낸다.**
   - 서버는 조각을 번호별 파일(`storage/uploads/<올리기 ID>/parts/<번호>`)로 받아 두고, 끝낼 때 번호 순서로 이어 붙인다.
   - 조각 크기를 768KB에서 1,000,000바이트로 키웠다 (프록시 한도 1MiB 바로 아래). 조각 수가 4분의 1쯤 줄어든다.
   - 동시에 보내는 수는 4다. 브라우저는 한 서버에 6개까지 함께 연결하는데, 다른 요청이 막히지 않게 남겨 둔다. 한 번 재 본 것으로는 6이 4보다 빠르지 않았다.
2. **조각과 영상 재생은 Vercel을 거치지 않고 서버로 직접 간다.**
   - 올리기를 시작하면 서버가 조각을 보낼 주소(`uploadUrl`)를 알려 준다. 서버의 `UPLOAD_PUBLIC_URL`로 정한다.
   - 화면 주소(Vercel)에서 서버 주소로 직접 보내는 것은 서버의 `WEB_ORIGIN`에 화면 주소가 있어서 허용된다 (CORS).
   - 직접 보내는 주소에 연결이 안 되면 화면은 시작한 주소(Vercel 경유)로 돌아가 계속 올린다.
   - 재생 주소는 서버의 `API_PUBLIC_URL`을 서버의 바깥 주소로 두어 직접 가게 한다. 코드는 바꾸지 않았다.
   - 올리기를 시작하는 요청과 그 밖의 API 요청은 그대로 화면 주소를 거친다 (작은 요청이다).
3. **끊기면 받은 데서 이어 올린다.**
   - 연결이 끊겨 실패하면 올리던 것을 지우지 않는다. 받은 조각은 서버에 하루 남는다.
   - 화면은 어느 올리기였는지를 파일의 이름·크기·고친 시각으로 기억한다 (브라우저 저장소). 같은 파일을 다시 올리면 서버에 어디까지 받았는지 묻고(`GET …/uploads/:id`) 빠진 조각만 보낸다.
   - 서버가 거절한 경우(영상이 아님, 크기가 틀림)는 예전처럼 올리던 것을 지운다.

## 결과

이 컴퓨터에서 서버로 올려 잰 값이다 (2026-11-28).

| 파일 | 방식 | 걸린 시간 |
|---|---|---|
| 23MB 영상 | Vercel 경유, 하나씩 (예전 방식에 가까움) | 4.9초, 3.5초 |
| 23MB 영상 | 서버로 직접, 4개씩 | 1.5초, 1.5초 |
| 200MB 파일 | 서버로 직접, 하나씩 | 17.4초 |
| 200MB 파일 | 서버로 직접, 4개씩 | 11.9초, 10.9초 |

- 좋은 점: 큰 영상이 더 빨리 올라가고, 영상 전송이 Vercel의 한도를 쓰지 않는다. 끊겨도 처음부터 다시 올리지 않는다.
- 200MB가 11~12초라서, 같은 연결이라면 1GB는 1분쯤으로 짐작한다 (재 본 것은 아니다). 실제 속도는 올리는 사람의 인터넷 올리기 속도에 달렸다.
- 서버에서 조각을 이어 붙이는 데 200MB에 1.4~2.2초가 걸렸다. 1GB면 10초 안팎이다.
- 한계
  - 이어 붙이는 동안 조각과 완성본이 함께 있어서, 영상 크기의 두 배만큼 저장 공간을 잠깐 쓴다.
  - 이어 올리기는 같은 브라우저에서 같은 파일을 다시 골라야 된다. 다른 기기에서는 처음부터 올린다.
  - 서버의 저장 공간(37GB)은 그대로다. 1GB 영상은 30여 개면 찬다. 회원마다 올릴 수 있는 용량의 한도도 아직 없다.
  - 영상 재생이 서버로 직접 가므로, 서버가 꺼지면 화면은 떠도 영상은 나오지 않는다 (예전에도 같았다).
- 나중에: 저장소를 Cloudflare R2 같은 곳으로 옮기고 브라우저가 거기로 직접 올리기 (조각을 8MB 이상으로 키울 수 있고, 서버 저장 공간을 쓰지 않는다). 회원마다 용량 한도.
