# 0004. 사용자 앱과 관리자 웹을 한 웹앱으로 합치기

- 날짜: 2026-11-11
- 상태: 채택
- 결정자: Yconic

## 배경

설계 문서(`ai-agent-architecture.md` 2장)는 사용자 앱(`apps/user-app`)과 관리자 웹(`apps/admin-web`)을 따로 두었다.
두 앱은 실행 주소가 달라 브라우저 저장소를 함께 쓸 수 없었다. 그래서 모의 데이터를 따로 들고 있었고,
관리자가 영상을 올려 공개해도 사용자 앱에는 나오지 않았다. 실행도 두 번 해야 했다.

## 결정

1. **두 앱을 하나의 Next.js 웹앱 `apps/web`으로 합친다.**
   - 사용자 화면: `/` (페이지 `src/app/(user)`, 코드 `src/user`)
   - 관리자 화면: `/admin` (페이지 `src/app/admin`, 코드 `src/admin`)
   - 실행은 `pnpm dev:web` 하나, 포트 3000
2. **모의 백엔드를 `src/mock`으로 옮겨 두 화면이 함께 쓴다.** 관리자가 공개한 콘텐츠와 올린 영상이 사용자 화면에 바로 나온다.
3. **예시 데이터를 하나로 합친다.** 공개 운동 4개(원래 사용자 앱 예시)와 관리자 흐름 시연용 3개(검수 중·초안·수정 요청).
   두 앱의 예시가 같은 운동을 서로 다른 상태로 갖고 있어서, 시연용 3개는 겹치지 않는 다른 운동으로 바꿨다.
4. **경계는 유지한다.** 사용자 화면 코드와 관리자 화면 코드는 서로 가져다 쓰지 않는다. 사용자 화면은 공개 중인 콘텐츠만, 필요한 칸만 받는다.
5. **스타일은 영역별로 나눈다.** 사용자 화면의 큰 글씨·따뜻한 바탕·굵은 초점 표시는 `.user-root` 안에서만 적용한다.

## 결과

- 설계 문서의 `user-app`, `admin-web`은 이제 `apps/web` 안의 두 영역을 가리킨다. 나머지 구조(api, 에이전트, MCP, 워커)는 그대로다.
- 작업 분담표에서 두 영역의 폴더가 `apps/web/src/user`, `apps/web/src/admin`으로 바뀌었다.
- 배포 단위가 하나가 된다. 실제 인증이 붙으면 `/admin` 아래 전체를 서버에서 막아야 한다 (지금은 모의 로그인).
- 사용자 화면을 따로 PWA로 설치하게 만들 때는 `/` 영역에만 manifest를 붙이면 된다.
